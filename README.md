# rust-blackboard — 跨设备黑板（AI 消息总线存储层）

Rust 实现的本地优先黑板服务器：KV 存储 + 全局 seq 时间轴 + audit 审计 + SSE 事件桥。

## 功能

- **KV 存储**：`notes/`（消息）`data/`（状态）`tasks/`（任务卡）`nodes/`（设备）命名空间
- **全局时间轴**：HLC seq（`/clock` 对时），增量事件可 `since_seq` 拉取
- **audit 审计**：所有写操作落 `audit.jsonl`（5MB 轮转 + ARCHIVE_KEEP=10 保留）
- **SSE 事件桥**：`GET /events` 实时推送变更（v0.6.1 修复：写入即广播）
- **设备注册**：`POST /register`（v0.6.3）→ device-id + token，存 `nodes/<name>/identity`

## 启动

```bash
# launchd 托管（推荐）
launchctl kickstart -k gui/$(id -u)/com.dsh.hr.blackboard-server

# 或手动
rust-blackboard --port 8792 --sse-port 8803 --data-dir <data-dir>
# 可选认证（v0.6.3+）：BLACKBOARD_TOKEN=<token> 环境变量
```

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /clock | 全局 seq + 权威时间 |
| PUT | /<ns>/<key> | 写 KV（body=value 扁平，无 value 包装）|
| GET | /<ns>/ | 列命名空间 |
| GET | /<ns>/<key> | 读单个 |
| DELETE | /<ns>/<key> | 删（占全局 seq）|
| POST | /register | 设备注册（device-id + token）|
| POST | /subscribe | 订阅 topic→callback |
| GET | /events | SSE 事件流（实时推送）|

### PUT body 契约（v0.6.8 起明确）

| 请求 body | 行为 |
|-----------|------|
| 合法 JSON（对象/数组/字符串/数字） | ✅ 原样落盘，返回 200 |
| 空 body | ✅ 落 `{}`（建键/占位），返回 200 |
| JSON `null` | ✅ 落 `{}`（与空 body 同义，旧语义保留） |
| **非 JSON 文本**（如裸字符串）+ `X-Body-Text: 1` | ✅ 落 `{"content": "<text>"}`，返回 200 |
| **非 JSON 文本**（无该头） | ❌ **400 `invalid body: expected JSON`**（v0.6.8 起；此前落 `{}` 且返回 200 = 静默丢数据） |

### 错误码语义（v0.6.8 起，服务端自带提示）

| 状态 | 含义 | 响应含 |
|------|------|--------|
| **400** | **键写法非法**（首段须纯小写字母 `[a-z]+`）或 body 非 JSON | `detail` / `reason` / `received` / `hint` / `legal_examples` |
| **404** | 键写法**合法**但该键不存在 | `detail` / `hint`（显式与 400 区分） |

### key 字符集（2026-09-11 探明，跨三方独立复现）

| 位置 | 规则 | 非法示例 |
|------|------|----------|
| **首段（命名空间）** | 必须**纯小写字母** `[a-z]+` | `cld-health` · `mac-mini` · `i9` · `foo_bar` · `ABC` → **400** |
| **后续段** | 合法字符集 = **`[A-Za-z0-9._-]`** | `:` `+` `@` `~` `!` 空格 → **400**；`_` `-` `.` → **200** |
| **后段含 `#`** | ★ **最危险**：`#` 是 URL fragment 分隔符 → **请求打到隔壁键**（服务端看不到） | `PUT …/data/x/a#b` 实际写 `data/x/a` |

> **★★ `#` 的静默改写（2026-09-11 HR 发现 / 星桥复现）—— 服务端无法防御**
> 实测（复现步骤与结果）：
> ```
> ① PUT data/x/a        {"v":"A"}   → 200
> ② GET  data/x/a                   → {"v":"A"}
> ③ PUT  "data/x/a#b"   {"v":"B"}   → 200   ← 无报错
> ④ GET  data/x/a                   → {"v":"B"}  ← ★ 隔壁键被静默覆盖
> ⑤ GET  "data/x/a#b"               → {"v":"B"}  ← 读也被静默重定向
> ⑥ PUT  data/x/a%23b（正确编码）    → 400      ← 服务端明确拒绝
> ```
> · **服务端为什么防不住**：`#b` 在到达服务端**之前**就被 URL 解析层当 fragment 丢弃，**服务端根本收不到正确的键**。
> · **正确编码就会得到明确 400**：`#` 不在后续段字符集 `[A-Za-z0-9._-]` 内 —— 故**编码规范的客户端安全**，危险只落在**字符串拼接**的客户端上。
> · **后果双向且都重**：读 → 读到**别的键**的内容，而「回读有内容 / 非空」这类判据会**全绿**；写 → **静默覆盖另一个键**（数据丢失），同样不报错。
> · **必须由客户端写前拦截**——不能指望服务端。与 `data//x`（影子键）同属"**你给的键 ≠ 你引用的对象**"。

> **★ 空段与前导斜杠的精确行为（2026-09-11 星桥实测，更正一处流传说法）**
> · `PUT data//x` → **200 且存为原样 `data//x`（不归一化）**；按**单斜杠** `GET data/x` → **404**。
>   ⇒ 故「空段键**写得进、读不到**」**不准确**：它对**同一畸形路径**可读，但在正常路径下**完全不可见** ——
>   它是一个**影子对象**（影子键：单斜杠的读者永远找不到它，`data/` 列举里却看得到 `data//x`）。
>   ⇒ 这才是客户端**必须拒绝**空段的实质理由：不是"格式难看"，而是会**写出一个正常路径看不见的对象**。
> · `PUT //data/x` → **200 且归一化为 `data/x`**（前导斜杠被宽容，不产生影子对象）。
>   ⇒ 实测对照：先写 `data/a`=A，再经 `//data/a` 写 B，回读 `data/a` 得 B ⇒ **确为同一对象**。
> 来源：明鉴（对抗式验证，41 键 / 0 漏点）发现前导斜杠宽容与空段可写；星桥独立复测并更正"读不到"的说法。

> **尾斜杠为什么危险**：`GET /data/reflect/` → **200**，但返回的是**整个顶层命名空间**（不是该前缀的内容，
> `total` 为全库键数）。因此「回读含标记即落地」这类判据在尾斜杠键上**必然假通过**——列举里必然含有你刚写的键串。
> 实测（2026-09-11）：`GET /data/` 与 `GET /data/reflect/answers/lab-mbp/` 返回**同一份全库列举**，
> 即**列举忽略前缀**；`limit`/`offset` 有效，可分页。
> 来源：HR（司库）发现 `validate`/`put` 对 `data/x/a:b` 判定矛盾并探明字符集；星桥独立复测确认。

> **★ 列举按完整前缀（v0.6.8 修复；上线前仍为旧行为）**
> 旧实现把路径**截断成第一段**，故 `GET /data/reflect/` 与 `GET /data/` 返回**逐字节相同**的全库列举。
> v0.6.8 起：`GET /data/` → `data` 全部；`GET /data/reflect/` → **仅该前缀**（`total` 亦为该前缀计数）。
> 实测同前缀请求体积：旧 **36,786,196 B** → 新 **45 B**。
> ⚠️ **该修复未上线时，行为仍是旧的全库返回**——据本条写逻辑前请先确认运行版本。

> **400 会伪装成「对象不存在」**（明鉴首例 2026-09-10）：拿到 400 的第一反应常是「卡没写进去」，
> 于是去查"为什么写失败"，而真正的问题是"键写法对不对"——**方向错了就白查一轮**。
> 服务端现在直接把 `detail` 写清楚；客户端侧 `scripts/bb-write.py`、
> `devices/dsh-plugin-reflect-collect/lib/upload.js`（四态 `present/absent(404)/bad-key(400)/unreachable`）也已有同类提示。

- **触发条件与 `Content-Type` 无关**：服务端不读该头，只看 body 能否解析为 JSON。
  实测：`text/plain` 裸文本与 `application/json` 头 + 裸文本**同样**命中。
- 写入方**必须回读校验**：`GET /<ns>/<key>` 确认 `value` 非空**且内容与意图一致**（仅看状态码不足以判定成功）。

## 时间戳语义（**重要**）

- 服务端所有 `ts`（含 `/clock.ts`、各卡 `ts`）为**服务端本地时间，且不带时区偏移**（如 `2026-09-11T05:07:21`）。
- 实测（2026-09-11）：本机与中央实例**当前同为 `+0800`**，故**今天无实际偏差**；但**格式本身有歧义** —— 跨实例/跨设备比较时间前，必须确认两端时区一致。
- **消费方纪律（建议写进各自协议）**：**指纹/时间戳只用于「我这一刻看到的是这个」，不能用于「它现在还是这个」** —— 时间戳带得再全，也解决不了"量完还会变"。
  来源：HR 实测某卡指纹在 **2 分钟内即过期**（00:48:48 记 `34413260…` → 00:55 实测已 `5c6bb1ef…`），故**要用于判定必须使用前重测，而不是引用**。
- 另一处易误用：**中央实例的 `/clock.host` 自称 `mac-mini`**（部署时未改该配置）→ **不要用 `clock.host` 判断"我在跟哪个实例说话"**；两实例确为**独立存储**（实测：写中央的键在本地 404、中央 200）。

## CLI 治理（v0.6.8 起）

| 项 | 行为 |
|---|---|
| `--help` / `-h` | 自解释用法，**exit 0** |
| `--tool-version` | 机器可读 JSON（版本单一来源 = `Cargo.toml`） |
| **未知旗标** | 打印用法 + **exit 2**，**不启动服务**（旧版会静默忽略并启动） |
| 退出码 | `0` 成功 · `1` 运行失败（如端口占用）· `2` 用法错误 |

## 设计要点

- 手写 HTTP/1.1 零外部依赖（serde_json + chrono 仅依赖）
- 数据格式与 Python 版一字兼容（snapshot.json + audit.jsonl）
- SSE 广播：写入端必须 broadcast（v0.6.1 修复前只存不广播，订阅端静默失联）
